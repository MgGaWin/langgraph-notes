## 已改变的用法

### MCP 内置接入

安装 `langchain[mcp]`，从 `langchain.mcp` 导入 `MCPAdapter`。独立的 `langchain-mcp-adapters/MultiServerMCPClient` 不再作为新课程的入口。

```python
from langchain.mcp import MCPAdapter

async with MCPAdapter(server) as adapter:
    tools = await adapter.list_tools()
    result = await tools[0].ainvoke({"a": 2, "b": 3})
```

这里 `server` 是示例的 FastMCP 服务实例。HTTP 服务可传 URL，本地脚本须传 `pathlib.Path`；多服务配置可传 `MCPConfig`。工具来源、认证、允许列表和审批仍由应用配置。新版支持服务端 elicitation 通过 LangGraph 中断交互；多用户认证与远程服务需按实际部署单独验证。[官方 MCP 指南](https://docs.langchain.com/oss/python/langchain/mcp)

### 人工审批

新示例使用 `HumanInTheLoopMiddleware(interrupt_mode="per_call")`。每个工具调用具有自己的中断 ID 和 `response_schema`。使用 `invoke(..., version="v2")` 得到 `GraphOutput`，再读取 `.value` 与 `.interrupts`：

```python
result = agent.invoke(inputs, config, version="v2")
pending = result.interrupts[0]
result = agent.invoke(
    Command(resume={pending.id: {"type": "approve"}}),
    config,
    version="v2",
)
```

`Command` 从 `langgraph.types` 导入，`config` 保持同一 `thread_id`，图须配置 checkpointer。`edit` 不能换工具名，参数经过工具 Schema 校验；无效恢复值报错后可修正重交。`respond` 用于人代替提问工具作答，有副作用的工具通常只开放 approve/edit/reject。旧 batched 模式仍可使用，但其 decisions 列表格式与 per_call 的 ID 映射不同。[官方 HITL 指南](https://docs.langchain.com/oss/python/langchain/human-in-the-loop)

### 事件流与工具参数

v3 返回运行流及类型化投影；常用 `stream.messages`、`message.text`、`stream.values`、`stream.tool_calls`。原始信封使用 `seq/method/params`。`on_chat_model_stream` 等字典对应旧的 `astream_events(version="v2")`，不能直接套用在 v3 上。

同步最终状态使用 `stream.output`；本次安装版异步使用 `await stream.output()`。同步同时消费多个投影使用 `interleave`，异步可并发读取投影。

模型消息流的 `message.tool_calls` 每次只产生新的参数字符串片段；按调用 ID 拼接，或用 `.get()` 得到解析后的完整参数。它和普通 `AIMessage.tool_calls` 列表不是同一种对象。前端消费者升级到兼容 tool-call-delta 的版本后再升级服务端；官方列出的 JS 客户端最低兼容版本为 1.2.6。[官方事件流指南](https://docs.langchain.com/oss/python/langgraph/event-streaming)

### Decisions 与决策中间件

`BaseDecisionModel` 是可 invoke/batch 的判断接口。问题支持 `Noul`、`Choice`、`Score`、`Box`；调用时同时传 `state` 和命名的 `questions`。`Noul` 表示是/否概率，`Score` 表示有序等级，不应把 0.5 概率误作中等程度。

`ModelRouterMiddleware` 和 `AutoModeMiddleware` 现在从 `langchain.agents.middleware` 导入，必须明确提供 `classifier=`。TypeSafe 的旧 experimental 中间件导入被弃用。课程本地分类器提供固定答案用于验证代码流程，不代表真实分类效果。使用真实 TypeSafe 需额外密钥。[TypeSafe 与 Decisions 官方指南](https://docs.langchain.com/oss/python/integrations/providers/typesafe)

### 摘要、refusal 与服务商能力

`SummarizationMiddleware` 新增 `summarizer=`，可使用不同模型、Runnable 或自定义函数。多轮历史依靠 checkpointer 和同一 thread_id 传递。

标准 `refusal` 内容块统一表达模型拒绝。不要仅依赖 `finish_reason="content_filter"`；拒绝与服务商的内容过滤不是一一对应关系。[官方模型文档](https://docs.langchain.com/oss/python/langchain/models)

部分模型支持会话中系统指令、工具和推理力度变化。OpenAI 的 `additional_tools` 需 Responses API 并置于 SystemMessage，`configuration_update` 放在 HumanMessage；Anthropic 的中途 SystemMessage 有位置和模型限制，支持工具增加/移除块。这些服务商专用块不能假设可用于任意 OpenAI 兼容端点。[OpenAI 集成](https://docs.langchain.com/oss/python/integrations/chat/openai)、[Anthropic 集成](https://docs.langchain.com/oss/python/integrations/chat/anthropic)

## LangGraph 的新增学习内容

- `version="v2"` 的 GraphOutput、StreamPart 及 Pydantic/dataclass 输出转换。
- 异步节点 `TimeoutPolicy` 的 run/idle 限制、`RetryPolicy`、`NodeError` 错误恢复、`set_node_defaults`。
- `RunControl.request_drain()` 在超步边界停止；使用检查点和相同线程恢复。
- `DeltaChannel` 以增量保存长历史。其 reducer 接收一批写入，必须保持确定性，不修改输入。
- `interrupt(response_schema=...)` 校验恢复结构，SQLite 关闭连接后重建图恢复。
- Functional API 的 `entrypoint/task`。外部副作用仍需业务服务提供幂等保障。

超时与错误恢复的可运行示例是 Python API；同步阻塞节点不能依赖异步超时机制。[官方容错文档](https://docs.langchain.com/oss/python/langgraph/fault-tolerance)、[Functional API](https://docs.langchain.com/oss/python/langgraph/functional-api)

## Deep Agents 扩展

最新稳定补丁版为 `deepagents==0.7.39`。0.7 的规划工具为 opt-in：需要时显式加入 `TodoListMiddleware`。后端传具体实例，`StoreBackend` 显式给 namespace；新文件内容为字符串。文件工具新增删除，write_file 会覆盖已有文件，分页读、glob/grep 的截断标记和允许列表也需留意。

Harness Profiles、上下文 Hub 后端、程序化工具调用与云端异步子 Agent 在官方指南中各有配置；需要模型、平台或运行环境支持，不能把本地最小示例当成已经验证了这些外部服务。LangChain 项目提供本地 Deep Agent 示例，复杂配置按需继续学习。[Deep Agents 概览](https://docs.langchain.com/oss/python/deepagents/overview)、[后端配置](https://docs.langchain.com/oss/python/deepagents/backends)

## 版本与数据边界

MCP、决策中间件、v3 和 DeltaChannel 中仍有 beta 功能；包本身发布稳定版不意味着每个 API 都已稳定。原有 v1/v2 接口保留兼容，不需要把全部基础例子机械地改成 v3。

普通 channel 与 delta channel 的检查点格式不同，已有线程不可直接切换。旧数据库没有在本次学习项目升级中被迁移或重新运行；新增持久化测试使用隔离临时数据库。对持久化过的 Deep Agents 线程，降级前应按官方恢复流程导出/迁移，不能只降包版本。

`docs/upgrades/2026-11-17-before.txt` 保存升级前包清单；`2026-11-17-after.txt` 与根目录 `requirements-lock.txt` 保存升级后本机完整环境；安装报告保存在同目录。该快照包含本机已有的可选包，面向 Windows/Python 3.14；其他平台使用分组 requirements 重新解析依赖。

依赖版本以可兼容组合为准：例如 LangChain 项目的 Google GenAI 依赖要求 `tenacity<9.2`，本次使用 9.1.4；不强制混装每个包单独的最大版本。RAG、Redis/Postgres、Gradio 等可选扩展仅在需要时安装并验证；真实模型服务效果需要账号单独实测。
